# Scale Out With Cloudflare

**Design proposal · spike baseline `173bc712d` · November 2026**


An operator enables Cloudflare once. Bifrost then provisions and maintains two demand-driven external scopes in its existing worker pool. Cloudflare Workers takes approved Python workflows and Cloudflare Containers takes qualified Linux overflow. The configured Kubernetes, in-process, or VM-provider primary retains its existing role and supplies warm or static local capacity. Region:earth means Cloudflare can place eligible work without a Bifrost location policy. Residency-bound work stays on the VM or the configured local primary. A jurisdiction setting is a later opt-in.

Use upstream's [capacity provider core and conformance contract](https://github.com/gobifrost/bifrost/pull/1423), [API-owned execution and remote control](https://github.com/gobifrost/bifrost/pull/1424), and [Containers provider lifecycle](https://github.com/gobifrost/bifrost/pull/1425) as the starting point. Each launcher registers as an `external` worker. Reuse prepare/start/observe/release, the signed control WebSocket, queue leases, and terminal ACKs. The managed Cloudflare prepare request is a known fork-only divergence described below. Any upstream proposal needs separate human review. Use ordinary Workers, Durable Objects and Containers.

## Operator Experience

1. In **Settings → Capacity → Scale Out With Cloudflare**, choose **Connect Cloudflare**. A Global platform administrator supplies an explicit account ID and write-only API token. Connect and Enable check active Workers and Containers entitlements for the selected account. The Containers entitlement establishes Workers Paid for this release. Show **Entitlement Required** if either cannot be verified. Do not request billing write or upgrade a subscription. Recommend a dedicated account and allow a shared one. Show that Workers Scripts Write is account-wide and can modify unrelated Workers. Acknowledge that Cloudflare terminates TLS and can see run-scoped credentials and workflow data. For an existing origin, Cloudflare also processes data in the execution runtime and TLS termination follows the configured ingress. Record the consenting caller, account, timestamp and consent text version before enabling.
2. Choose **Managed Tunnel** or **Existing HTTPS Endpoint**. Managed Tunnel is supported on both the single-host Compose installation and Kubernetes/Helm in its first release. Existing HTTPS Endpoint uses a dedicated Bifrost worker ingress behind the operator's proxy. Show the validated ingress and unsupported perimeter requirements before saving.
3. Review **Capacity Limits**, **Monthly Spend Limit**, and **Workload Placement**. Show primary type, primary and shared limits, Workers launcher and slot limits, and Container count, size and workflow slots. Validate the cost envelope before saving. The pilot starts with zero warm cloud instances, one two-slot Workers launcher and, if selected and entitled, one Container with one workflow slot. Residency-bound work stays on the local primary. The operator can propose, accept or revoke workflow approvals in product from this release's first Workers phase.
4. Press **Scale Out With Cloudflare**. Shared PlatformJob progress shows provisioning, connectivity, signed hello and admission. **Capacity** shows desired, reserved, starting, ready, busy, draining and unconfirmed counts, queue age, last successful probe, deployment revision, approvals and **Estimated Spend** with its policy period and advisory Analytics sample. Show **Cloudflare Capacity Unavailable** when Cloudflare cannot allocate a Container. Keep compatible work queued for the VM or other configured primary and avoid repeatedly requesting capacity during cooldown. Show **Spend Ledger Unavailable**, **Budget Reached**, **Cleanup Pending**, or **Action Required** with the affected scope and remedy. Read the existing capacity resource on load, reconnect and notification invalidation.
5. **Scale In** closes cloud admission and drains to zero, retaining provisioning, policy and any ongoing provider charges. **Scale Out With Cloudflare** resumes the installation. **Disconnect** drains and removes all owned resources. Retain its credential and inventory until deletion is verified. A valid replacement token for the same account can resume a blocked disconnect. Purge the credentials after the final readback and retain an audit receipt so the operator can revoke their token.

## Reachability and Credentials

| Option | Authority and responsibilities |
| --- | --- |
| Managed Tunnel | Recommended on supported installs. A preinstalled supervised `cloudflared` sidecar is dormant in Compose. Bifrost owns the method/path allowlist and authentication on that ingress in both modes. Probe the configured public origin from Cloudflare and verify successful signed hello, scoped SDK access and negative routes. Bifrost refuses activation when the proxy exposes an ordinary API upstream through the worker hostname, allows redirects or fails the required probes. |
| Access or mTLS | Additional perimeter authentication may be required by the operator. Keep managed Access/mTLS outside initial delivery. Qualify WebSocket upgrade, refresh and SDK calls for both runtimes before supporting it. Workers mTLS has proxied-zone restrictions and a standing Access token would add a separate shared data-plane credential. [Access mTLS](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/mutual-tls-authentication/) · [Workers mTLS](https://developers.cloudflare.com/workers/runtime-apis/bindings/mtls/) |

The dedicated Bifrost ingress fails closed on host, normalized path, method and WebSocket upgrade before routing into the API. Version the allowed operations with the runtime manifest and derive them from the canonical SDK route policy and actual API route registrations. Inventory the SDK families for organizations, configs, files, integrations, tables, events, forms, agents, agent runs, explicit roles/users operations and authorized PlatformJob reads. Map supported operations to exact templates and methods. Include worker control, runtime log writes, token refresh, and Linux module resolution and scoped source GETs. Linux package inventory, requirements bytes and package-tool commands currently travel through the authenticated control socket, then the helper may fetch approved distributions from package origins. Qualify both paths and include any confirmed package HTTP routes in the versioned matrix. There is no reason to expose the platform package administration router just to bootstrap Linux. Deny unrelated admin routes, login, OpenAPI, fixture endpoints and general `/api/*`. Tunnel ingress and the existing proxy provide defence in depth. Signed hello, original-caller authorization and run liveness remain mandatory after the ingress check. Add body/rate bounds and cross-check decoded/encoded path and method behavior across both layers.

Keep `BIFROST_SECRET_KEY`, the primary worker capacity token, the Cloudflare control-key derivation root, the Cloudflare API token and DB credentials on Bifrost. The managed provider receives a **separate**, per-installation, per-scope, rotatable bearer for authenticating its capacity API. It grants no primary capacity, Cloudflare management, or launcher identity authority. Store it in that provider's Worker secret binding and in Bifrost encrypted storage. The launcher DO and Container get only their derived incarnation keys and the scoped run credentials needed for work. Remove provider-side control-key derivation. Workers Scripts Write already grants the ability to replace the provider code, so public-key request signing would add a second credential protocol without addressing that account-level boundary.

Before prepare, Bifrost commits the reserved incarnation, an immutable caller-allocated resource UID and the installation's active derivation-root version. The Workers protocol-2 path derives the control key from the encrypted root using the installation ID, root version, scope, worker ID and resource UID. Bifrost sends the resulting key over TLS in prepare and verifies the response matches its reservation. Signed hello uses the same pinned version during drain. The managed request shape is a fork-only divergence from #1423 and #1424. Primary providers keep their upstream contract. Test same-key replay, changed UID or key rejection, scope and bearer mismatch, observe-before-retry after unknown prepare or start, tombstone replay, cross-scope hello rejection and absence of key bytes from readback. Persist the derived key only where launcher restart requires it, bound to the exact incarnation. Strip it from Linux child processes and purge it on release. Bound reconnect and workload lifetimes and expire runtime leases when Bifrost stops renewing them.

The fork advertises capacity protocol 2 for managed Workers on the existing `/v1` routes. Its PUT requires `resource_uid` (32 lowercase hex characters) and `control_key` (64 lowercase hex characters). The API binds the HMAC to the reserved scope, incarnation and UID under the managed protocol domain. The provider authenticates the PUT with the independent scope bearer, holds the key only while prepare is unsettled, and stores a digest for replay checks. Readback contains the UID and lifecycle state. The controller and provider must be upgraded after Scale In because the prior Workers prepare wire derived its keys from the bearer. Primary provider protocol 1 remains the default for the upstream #1423/#1424 HTTP conformance harness. The local Workers suite explicitly selects `--managed-cloudflare` and adds tests for the managed identity fields and independent bearer.

Use Bifrost's platform secret encryption service for versioned API token, scope bearers, derivation root and connector credential records. Only the trusted controller or supervisor with that purpose gets plaintext. Audit credential versions and actor, excluding values from payloads, logs and status. Rotate the API token only to a replacement validated in the same account and zone, then atomically switch references and resume by readback. Rotate scope bearers independently using a bounded two-version acceptance window, then remove the former binding after verification. Treat any secret-binding deployment that can restart executing DOs as a drain-first change. Rotate the derivation root after drain and before fresh incarnation allocation. Validated API-token rotation leaves existing launcher identity intact. Provider token revocation, loss and remaining cleanup are handled below.

## Scaling, Placement and Spend

The fork's `api/src/services/kubernetes_control.py` requires both external-provider credentials and the hello opt-in for Cloudflare burst. Selecting a primary capacity URL skips the Kubernetes worker pool loop. Kubernetes isolated-build reconciliation is independent and can still run if authorized. `external_worker_pool_loop` reads cloud settings just once before entering its loop. Phase 1 changes that topology.

- Start a Bifrost-side Cloudflare supervisor independent of primary selection. It follows the current DB policy with revisioned wakeups and a bounded sweep, claims fenced per-install/controller ownership and starts, refreshes or retires cloud scope controllers at runtime. API replica failover adopts durable resources and reservations. Provider endpoint, bearer and derivation lookup for hello come from the immutable reservation's scope and policy binding. Closing admission is immediate under the reservation fence. Keep retirement/reconnect supervision until all owned releases settle, then stop the scope controller. Phase 1 ships Kubernetes alongside cloud on the same API, along with VM-provider and in-process primaries. The primary's own boot configuration remains authoritative.
- Reuse shared packing and claim predicates. For Kubernetes and VM-provider primaries, let the reconciled primary pack and provision first to its effective ceiling, then consider cloud when compatible queue age/depth persist. For in-process workers, count registered static local slots from existing heartbeats and memory admission. Saturation means the configured local cohort is healthy and has no eligible fitting headroom. There is no managed external ceiling to read in this mode. Keep Fast Path and isolated-build behavior with their existing owners, and hold cloud starts on unknown primary health.
- Use queue age and compatible demand, active claims, prepared slots, worker memory fit, warm floor where applicable and idle cooldown. Prefer existing slots to new starts. Enforce the shared managed-worker limit, per-scope launcher and instance limits, and aggregate slot and tenant fences in the reservation transaction. Starting and unconfirmed exits count until verified. Containers take qualified Linux overflow. On hosted allocation refusal display **Cloudflare Capacity Unavailable**, cooldown the scope and keep work eligible for the configured VM or other primary. Peer-scope failure only closes admission where its state is required.
- Use Cloudflare's default placement behavior without Smart Placement tuning or DO location hints. No jurisdiction configuration is sent. Enforce a residency exclusion in planning and claims. Measure time to ready, API/SDK RTT, queue-to-entry and usage by direction in hosted runs. Longer origin round trips and Container egress can increase cost and latency even with healthy capacity. [Container placement](https://developers.cloudflare.com/containers/concepts/architecture/) · [Container pricing](https://developers.cloudflare.com/containers/platform/pricing/)
- At policy save, price one full fleet lifetime conservatively using each scope's physical instance or launcher cap, maximum lifetime, bounded cleanup margin, and published usage rates. Include the worst-case configured CPU, memory and disk where applicable, requests, logs, and transfer. Reject a policy if this envelope exceeds the monthly usage limit. Multiple waves and provider metering lag can still increase monthly cost.
- At admission, price the Bifrost ledger for the current UTC calendar month. Price launcher duration from its reservation-to-deletion lifetime at 128 MB, control traffic at the controller cadence and each managed capacity request at its deployment CPU cap. Reserve tenant host duration, CPU and possible Dynamic Worker creations through each finite route deadline and warm tail. Price launcher workload as the greatest of the deployed cap, sealed count and terminal high-water count per meter. Status lists each included rate and shows the monthly fee separately as **Workers Paid Subscription (Billed by Cloudflare)**.
- Close admission at the threshold or if ledger evidence is unavailable or inconsistent. Account history survives Scale In, deployment replacement and same-account reconnection. Incomplete pre-migration history closes admission through the rest of that month. Let existing bounded work settle and retire. There is no monetary reservation per claim. Spending can exceed the admission threshold.
- Optional provider blocking limits cover Workers and Durable Objects across the entire account. They do not cover Containers and can interrupt recovery calls. Read them back if authorized. The default flow leaves account-wide settings under operator control. [Cloudflare spending limits and alerts](https://developers.cloudflare.com/billing/manage/spend-management/)

**Account Analytics Read** can query sampled Worker requests and CPU by exact script name. Attributable Durable Object usage failed the freshness and completeness checks. Analytics is advisory. Status shows the difference between sampled Worker requests for the owned scripts and the Bifrost request proxy. Missing or divergent Analytics results never close admission. The estimate covers the launcher ledger and named reservations. Cloudflare invoices also reflect shared or provider-generated activity and account billing terms. ## Provisioning Adapter Boundary

The resource journal uses a target (installation, account, scope, kind and exact name), a creation effect ID, a desired revision and an artifact digest. Provider readback adds an opaque resource ID and version witness. An adapter can use a provider version or a digest of independently read deployment state as the witness. Preserve provider IDs verbatim, including the Container application ID. Reconcile receives an observation only after the adapter has checked its owner and version. Verified absence excludes an earlier effect that can still arrive.

Phase 0 at `61a77ea11` supplies the operation map for product adapters. REST handles account identity and entitlement reads, multipart Worker upload with a durable ownership marker, exact script and namespace readback, and Container application and image preparation. OCI copies image content by digest. The pinned `cf` path supplies scoped registry tag inventory and deletion for an exact repository and digest. Route each operation through its qualified path. A timeout leaves the journal open for readback on that same path.

Connect and Enable independently verify account identity and active boolean-true workers.enabled and containers.enabled using REST. The latter establishes Workers Paid through Account Settings Read. The operator cf subscription read remains hosted evidence. Keep the account credential on Bifrost. Send a scope bearer only as the private secret binding on that scope's capacity Worker.

## Lifecycle and Recovery

Register `capacity.cloudflare_enable`, `capacity.cloudflare_reconcile` and `capacity.cloudflare_disable` on trusted Bifrost infrastructure. Reconcile owns automatic upgrades in Phase 4. An explicit upgrade action can request the same reconcile path. Disable handles Scale In and Disconnect. Version job payloads and include IDs and desired revision only. Use the shared PlatformJob policies for deadlines, retry, waiting, cancellation and progress. The fenced scheduler deduplicates jobs on config changes and health sweeps. Persist the installation, credential references, current deployed artifact revision and resource inventory. Serialize incompatible actions by installation and desired revision. The durable resource record stores effect intent and readback. PlatformJob owns job leases and terminal state.

- **Recover and repair.** Before every external mutation, verify the account, target and current ownership, including installation identity, recorded provider IDs and expected before state. A create requires a pre-journaled deterministic name and an absence check. A timeout or lost response requires exact readback before a second mutation. Keep reconciling ambiguous in-flight effects and their potential late arrivals until verified. Never adopt a foreign resource by prefix or delete shared configuration. Honor provider backoff. Count unconfirmed exits against capacity and report remaining exposure. Keep **Cleanup Pending** until the complete inventory closes.
- **Upgrade.** Reconcile always closes cloud admission, drains existing claims, collects terminal ACKs and verifies physical retirement before changing any runtime artifact. Keep worker ingress and the control adapter alive through drain. The installed Bifrost version must serve the preceding wire contract through drain, or the release procedure must complete Scale In before rolling the API. Redeploy matched Workers modules and Container image, verify exact digests, capabilities and a no-effect signed canary, then re-admit. The configured primary serves compatible work during the cloud pause. There is one deployed admission revision and no product rollback workflow. On failed deploy or canary, leave Cloudflare paused and resume repair with the desired release. Unexpected DO resets use the existing inventory and ACK replay path. An interrupted attempt classified `uncertain` keeps its original claim and is never redispatched based on transport failure alone.
- **Scale In and Disconnect.** Close admission and starts under the pool fence. Let active work settle or apply existing deadline/lease-loss handling. Confirm release and physical stop before deleting the owning resources. Remove public bindings/entry points in dependency order, independently delete owned Container applications, scripts and namespaces, then delete owned registry tags after reference checks. Shut down owned connector sessions, remove DNS and the tunnel, and verify absence or deletion tombstone and zero connectors. Managed install service definitions can remain dormant after the connector token is erased. Verify zero owned active resources before purging credentials. A Worker delete alone does not remove the app. [Containers resources](https://developers.cloudflare.com/api/resources/containers/)
- **Revoked or narrowed token.** Separate authenticated provider denial from timeout and 429. Once denied, show **Reconnect Required**, close new admission, and stop provisioning. Permit only bounded drain/release via the separate scope bearer while it works. Require fresh management-credential health to renew active runtime leases outside drain. Retain inventory and show what remains billable or unverified. A validated same-account replacement resumes by readback and restores management authority before any new launch. Provider-side resources can remain until valid authority returns, even after local leases expire.
- **Worker deleted, tunnel down, or no Container available.** Close affected admission. For a deleted Worker, fence its lost incarnation(s), settle uncertain work using existing loss semantics, and account for surviving namespaces/apps before repair. For tunnel loss, allow bounded reconnect and terminal replay on the same identity, inspect the connector/DNS/ingress, and repair only verified owned resources. For a capacity refusal, back off, release the reservation after confirmation, and keep unstarted work available to the configured primary. None of these cases replays a potentially started effect.

**Retire Legacy Cloudflare Workers** reports older Workers reservations with no installation pin. Recover the matching capacity endpoint and its scope bearer from the original enrollment. Send `GET /v1/workers/{worker_id}` with that bearer and `X-Bifrost-Capacity-Scope`, and compare the returned `resource_uid` with the job record. Release the same worker by sending `DELETE` to that URL with the same scope and a JSON body containing the matching `resource_uid`. Keep the same UID's `deleted` readback. A missing endpoint or an ambiguous UID requires recovery of the original enrollment record before proceeding. Have the platform database operator record verified retirement for the exact unpinned worker and retain the readback with the incident. Retry the Cloudflare job after all listed workers have verified retirement.

In Phase 1, scope bearer rotation begins after Scale In. It verifies deletion of the previous deployment before staging the next bearer for Enable. Enable retires any remaining older revisions before provisioning, and usage checks include retained receipts for those revisions. Account-token rotation purges encrypted predecessors when validated account and ownership readback commits the switch. If later write authorization fails, submit another explicit replacement. Uploads and scope-deletion confirmation retain the mutation fence through provider readback because a job lease can expire during an unconditional provider write.
