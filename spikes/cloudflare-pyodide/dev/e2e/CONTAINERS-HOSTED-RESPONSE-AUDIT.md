# Containers Hosted Runner Response Audit

This audit covers `--containers-hosted-shape --hosted-containers-config` with
the published rc03 images. The runner uses Existing HTTPS. Its Cloudflare
requests are account-scoped GETs. Credential verification and provider
mutations during the trial go through the product. Local fixture hooks and
the Managed Tunnel and Workers Upgrade modes are outside this call path.

## Cloudflare and Ingress

| Runner check | Source evidence and disposition |
| --- | --- |
| Account inventory HTTP status and JSON | Require HTTP 200 and a successful v4 envelope with an array result. The unbounded Containers applications read also accepts a raw array. The numbered or cursor metadata must be an object when present. Require unique, nonempty IDs because an unidentifiable row cannot establish collision-free inventory or verified absence. [List Worker Scripts](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/list/), [List Namespaces](https://developers.cloudflare.com/api/resources/durable_objects/subresources/namespaces/methods/list/), [List Applications](https://developers.cloudflare.com/api/resources/containers/subresources/applications/methods/list/). |
| Worker scripts | The public SDK models the scripts list as a single page. `id` is the script name. The runner compares exact names and captures `etag` if present. The rc03 product verifies each owned script through its exact settings URL and journal. [Workers Scripts SDK](https://developers.cloudflare.com/api/go/resources/workers/subresources/scripts/methods/list/), [product reader](../../../../api/src/services/worker_pool/cloudflare_workers_rest.py). |
| Durable Object namespaces | The captured envelope reports `page=1`, `per_page=20`, `count=20`, `total_count=23` with no `total_pages`. Follow page numbers until the unique count reaches the stable total, as rc03 does in `_script_namespaces`. The reported size can differ from the requested size. If a total is absent, explicit page count or a reported page size can establish completion. Reject empty continuations against an outstanding total, malformed or conflicting metadata, and duplicate IDs. `script`, `name`, and `class` are optional. Unattributed namespaces remain in the snapshot. Match owned script names exactly and use recorded namespace IDs for teardown. [List Namespaces](https://developers.cloudflare.com/api/resources/durable_objects/subresources/namespaces/methods/list/), [product reader](../../../../api/src/services/worker_pool/cloudflare_workers_rest.py). |
| Containers applications list | The documented first request defaults to all applications when both pagination parameters are omitted. This makes the captured array without `result_info` complete on that request. Follow `next_page_token` when provided and validate `page_token` if echoed. A bounded full page with no continuation or total cannot prove absence. Match exact application names and require one trial application after Enable. The rc03 reader uses bounded pages for its ownership and cleanup queries. [List Applications](https://developers.cloudflare.com/api/resources/containers/subresources/applications/methods/list/), [product reader](../../../../api/src/services/worker_pool/cloudflare_containers_rest.py). |
| Registry image probe | The runner invokes the rc03-pinned `cf` through the product tool wrapper, checks its exact version and selected account, and expects the captured JSON array of `{name, tags}` rows. The product's `ContainerRegistry._tags` expects the same shape and allows both repository and account-qualified repository names, including empty tag arrays. Normalize that prefix, reject duplicate repository keys, and compare exact repository names. Keep the token on stdin to the probe. [CLI JSON output](https://developers.cloudflare.com/cf/get-started/), [product registry reader](../../../../api/src/services/worker_pool/cloudflare_containers_rest.py), [image probe](container-trial-planner.py). |
| Exact provider readback | HTTP 200 requires v4 success and the result. A teardown 404 is checked by HTTP status without parsing its error body. Script settings and namespace object reads are additional direct lookups after complete inventory and product journal checks. Their successful response envelopes are documented. The exact deletion-time error response is an exercised runner check, with the hosted result still to be witnessed. [Script Settings](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/settings/methods/get/), [Namespace Objects](https://developers.cloudflare.com/api/resources/durable_objects/subresources/namespaces/subresources/objects/methods/list/), [product Workers cleanup](../../../../api/src/services/worker_pool/cloudflare_workers_rest.py). |
| Container placement | Compare both instance ID and application ID against the settled reservation. Accept `status.state` of `stopped` or `inactive`, as rc03's `observe_instance_outcome` does. The product also checks the pinned image and timestamps before writing settlement. Require a single claim and a non-null stopped receipt before the provider read. [Container instance GET schema](https://developers.cloudflare.com/api/typescript/resources/containers/), [product placement reader](../../../../api/src/services/worker_pool/cloudflare_containers_rest.py). |
| Application health and identity | At Scale In require integer zeroes for `health.instances.active` and `starting`, the counters for the Durable Object scheduling variant. Additional fields are allowed. This matches the product health veto. Re-enable must return the same application ID, and Disconnect verifies the exact ID and exact name are absent. Four scripts and six namespaces are rc03 deployment counts, not Cloudflare response schema. [Application GET schema](https://developers.cloudflare.com/api/resources/containers/subresources/applications/methods/get/), [product application reader](../../../../api/src/services/worker_pool/cloudflare_containers_rest.py), [product deployment](../../../../api/src/jobs/platform/cloudflare_enable.py). |
| Hostname and DNS | The runner accepts a lowercase DNS hostname in its private config and requests a dedicated Existing HTTPS origin. Public DNS resolution and address validation happen in the image's `probe_public_worker_ingress`. A proxied CNAME can resolve to A/AAAA records. The runner has no CNAME-answer assertion, fixed address count, or IP-family requirement. The manual checklist checks the configured CNAME target separately from public resolution. [Tunnel DNS](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/dns/), [CNAME flattening](https://developers.cloudflare.com/dns/cname-flattening/set-up-cname-flattening/), [product ingress probe](../../../../api/src/services/worker_ingress_probes.py). |
| TLS and preflight tool output | The private Compose API is checked separately from public ingress. The worker invokes the product probe with normal certificate trust and the hostname as SNI. It checks protected routes and the WebSocket upgrade with redirects disabled. The runner consumes the tool's JSON observation, exit code, `reachable`, `remote_launcher`, the pinned rc03 test vector of 100 routes, and nonempty connection evidence. No Cloudflare header, issuer, certificate subject string, or edge address is pinned by the runner. The hostname must be covered by the actual edge certificate. [Edge certificates](https://developers.cloudflare.com/ssl/edge-certificates/), [probe wrapper](../cloudflare-launcher/preflight-compose-worker.sh), [product ingress probe](../../../../api/src/services/worker_ingress_probes.py). |
| Egress witness | The runner reads Enable's outcome and settled canary rows. The product, not the runner, handles the Bifrost ingress markers, guest trust, redirects, and denial classification. The API must first resolve the alternate peer and reach TCP 2053 and 8443. Cloudflare documents proxy support for these ports, which does not guarantee reachability from the trial API or guest denial. Record those as trial observations. [Cloudflare ports](https://developers.cloudflare.com/fundamentals/reference/network-ports/), [supervisor probe](../../../../api/src/worker/remote/container_egress.py), [product qualification](../../../../api/src/jobs/platform/cloudflare_enable.py). |
| Tunnel and config reads | The hosted runner reads its private JSON config and Docker's project, port and network information. It does not read Cloudflare DNS or Tunnel configuration endpoints in Existing HTTPS. The operator's ingress setup and teardown use the dedicated hostname and exact provider IDs. A remote Tunnel configuration has a v4 result with `config.ingress`, and the DNS record result has its configured type, name and content. These fields belong to the operator check and Managed Tunnel reader. [Tunnel configuration GET](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/configurations/methods/get/), [DNS record GET](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/get/), [product Managed Tunnel reader](../../../../api/src/services/worker_pool/cloudflare_tunnel_rest.py). |

The snapshot needs the complete account inventory rather than the product's
owned-resource subset. The synchronous runner uses the product readers'
continuation signals without importing or replacing their async adapters in
the published image. Trial names still come directly from the pinned image.

## Bifrost and Local Evidence

| Runner check | Source evidence and disposition |
| --- | --- |
| Private config, Docker and login | Require a private config file, explicit account ID, isolated trial Compose project and private service IPs with no host port bindings. The runner accepts the Cloudflare management origin or a private stub origin. Require HTTP 200 and `access_token` for the local password login, and 2xx for subsequent Bifrost calls. These are the runner's safety fence and Bifrost auth contract. [Runner](combined-rehearsal.py). |
| Review and plan | Require the suggested Workers preset and $75 limit, staged credential reference, matching account and receipt, zero prewarming, opt-in policy, 100 hours available, valid price envelope, and no pre-existing installation or canaries. Image probe output must bind the receipt account and installation, derive four scripts and the application from rc03 naming, and resolve the registry repository/tag from the product destination. These are pilot settings and release contracts. [Bifrost capacity models](../../../../api/shared/models.py), [activation](../../../../api/src/services/worker_pool/cloudflare_activation.py), [image probe](container-trial-planner.py). |
| Activate and job results | Parse accepted job IDs as UUIDs. Poll public status, attempt, optional progress/error/result, and require the operation's terminal success outcome. Enable additionally requires remote launcher connection evidence, open admission, and exactly one settled canary per Enable, with a total cap of two and explicit cleanup/backoff stop codes. [PlatformJob models](../../../../api/src/models/contracts/platform_jobs.py), [Enable](../../../../api/src/jobs/platform/cloudflare_enable.py), [Scale In and Disconnect](../../../../api/src/jobs/platform/cloudflare_capacity.py). |
| Plan identity, scheduler and spend | Match installation UUID, revision and admission state, and keep the same revision on retained Scale In/Enable. Consume optional Containers lane diagnostics and ready spend with decimal settled/reserved USD, and apply the configured high-water and time fences. Counts of canaries and settlement are SQL counts against the pinned schema. Provider usage and billing remain separate manual records. [Capacity status and spend models](../../../../api/shared/models.py), [status assembly](../../../../api/src/services/worker_pool/cloudflare_status.py), [reservation schema](../../../../api/src/models/orm/cloudflare_capacity.py). |
| Workflow, approval and saturation | Require the seeded provider organization, preserve workflow org identity, parse execute IDs, and check the current Linux review SHA, installation, two expected findings, approved state and cleared revision after revoke. Verify primaries are idle before holds, memory saturation is observable, and holds cancel or finish on release. Require workflow Success with the fixture child/native output. These checks use Bifrost responses, SQL, and the authored workflow. [Approval models](../../../../api/src/models/contracts/cloudflare_approval.py), [hold witness](wait-primary-hold.py), [runner](combined-rehearsal.py). |
| Teardown ledger and snapshots | Require `installation: null`, absence of script names and both journaled/attributed namespaces, zero active incarnations, unreleased slots, credential ciphertext, and non-absent owned rows. Compare opening and closing identities and report foreign drift separately from trial leftovers. Always attempt the closing snapshot even when teardown fails, keeping the original journey error. [Capacity journal schema](../../../../api/src/models/orm/cloudflare_capacity.py), [runner](combined-rehearsal.py). |
